# Amazon BS Market Radar V2.0 UI Audit

审计日期：2026-08-30  
审计范围：公开网站、`web/app` 页面、全局样式、共享组件、现有数据视图与测试。  
审计方法：源码检查、线上 1366×768 首屏检查、现有测试与生产构建基线。

## Current Visual Architecture

- 技术栈为 React 19 + Vinext/Vite + Cloudflare Sites，页面使用 App Router 风格的服务端组件与少量客户端组件。
- 全站布局由 `app/layout.tsx` 和 `SiteShell.tsx` 提供；页面视觉主要由单个压缩式 `globals.css` 与补丁式 `enhancements.css` 控制。
- 线上实际是浅色页面配深色顶栏，不是完整 Dark Theme。1366×768 首页首屏主要出现数据就绪 Hero、四个质量 KPI、跨榜单矩阵与 99/100 就绪雷达。
- 首页总高度约 1472px，真正的明显排名变化在首屏以下，系统状态与技术条件比业务信号更突出。

## Existing Design Tokens

- `:root` 只有 `--nav`、`--ink`、`--muted`、`--line`、`--bg`、`--blue`、`--green`、`--amber`、`--red`、`--panel`。
- 现有 Token 能表达基础颜色，但没有 Surface Level、焦点、文字层级、间距、圆角、阴影和语义状态体系。
- 大量颜色直接写死在组件样式中，尤其是卖家分析、按钮、图表点、状态卡和输入框。

## Existing Shared Components

- `SiteShell`：品牌、八个一级导航入口、静态数据状态文字和 Footer。
- `PageHeader`：Eyebrow、标题、长描述和右侧工具。
- `QualityBadge`：四种颜色状态。
- 其余 KPI、排名、产品、信号、空状态、图表 Tooltip、市场上下文均由页面内重复 JSX 实现。

## Existing Table System

- 全局 `table/th/td` 样式被所有表格共享。
- 优点：已有横向滚动容器、基础分隔线和文本截断。
- 缺口：没有 Sticky Header、统一数字右对齐、排序状态、密度规范、ProductIdentity、RankDisplay/RankDelta；榜单把 ASIN 独立成列，Amazon 长标题占据过高视觉权重。

## Existing Chart System

- 没有图表依赖；产品详情使用 CSS 定位的历史排名点。
- Y 轴已经按 #1 在上、#30 在下，方向正确。
- 缺口：无连接线、统一 Tooltip、Top10 Zone、事件标记、键盘可访问说明与统一图表 Token。

## Existing Navigation

- 八个一级入口：总览、榜单、产品趋势、洞察、卖家分析、智能报告、报告、方法说明。
- 卖家分析使用大面积渐变 Active-like CTA，所有页面都显示；当前路由没有可靠 Active State。
- 宽度小于 1050px 时导航直接隐藏，没有移动端菜单。
- Data Status 是静态文字，不可打开；没有 Activity/Alerts Drawer。

## Existing Responsive Strategy

- 只有 1050px 和 650px 两个断点。
- 卡片会从四列变两列或一列，表格容器可滚动。
- 主要问题：导航在平板宽度直接消失；Header 工具易横向拥挤；页面没有针对 1366×768 的首屏信息层级目标；抽屉、Tooltip 和图表没有响应式规则。

## Existing Accessibility

- 已有 `aria-label`、部分 `role=status`、Seller Workspace 的 `aria-current` 与局部 `focus-visible`。
- 主导航没有当前页状态；通用按钮、链接、Tab 和输入框缺少一致可见焦点；日期按钮不是实际日期控件；颜色 Badge 的文字语义存在但不统一。
- Loading 仍以“正在……”纯文字为主，No Data、Loading Error、Incomplete Data 没有统一组件。

## Duplicate UI Patterns

- KPI 在首页、产品详情、报告、卖家证据中有四套结构。
- Badge 同时使用 `QualityBadge` 和手写 `span.badge`。
- Rank 与 Delta 在首页、榜单、产品页、卖家信号中分别格式化。
- 空状态、错误状态、产品链接、证据说明、筛选器和报告卡重复。

## Hard-coded Styles

- `globals.css` 和 `enhancements.css` 含大量直接色值、圆角、阴影、间距和字体大小。
- 页面级选择器依赖 DOM 顺序，例如 `.rankingTable td:nth-child(2)`。
- 两份 CSS 形成“基础样式 + 后加补丁”，缺少稳定组件边界。

## Components That Can Be Reused

- `SiteShell` 的布局职责、Footer 与原生导航降级能力。
- `PageHeader` 的服务端组件结构，但需要允许无 Eyebrow 的紧凑模式。
- `QualityBadge` 的语义文字和 Tone 思路，可扩展为统一 Badge System。
- `RankingExplorer` 的类别 Tab、搜索和 Top10/20/30 过滤。
- 产品详情的历史数据与反向 Y 轴。
- `AnalysisCenter`、`SellerIntelligenceCenter`、`ReportsArchive` 的数据加载与错误隔离。

## Components That Need Refactor

- `SiteShell` → 紧凑品牌、六项一级导航、Active State、Alerts、Data Status、Methodology、移动菜单。
- `PageHeader` → 中文标题优先、短 Subtitle、统一 MarketContext 和低权重日期。
- `QualityBadge` → `StatusBadge` / `AlertBadge` / `EvidenceBadge`。
- 新增 `MetricCard`、`SignalCard`、`RankDisplay`、`RankDelta`、`ProductIdentity`、`ProductTypeBadge`、`MarketContext`、`DataStatusDrawer`、`ActivityDrawer`、`EmptyState`、`Tooltip`、`RankTimeline`。

## Highest Impact Visual Problems

| Priority | Problem | Evidence | Impact | Recommendation |
| --- | --- | --- | --- | --- |
| P0 | 首页技术状态压过业务信号 | 1366×768 首屏只看到数据就绪、质量 KPI、矩阵与就绪雷达 | 用户必须向下寻找异动 | 首页改为 Market Summary、4 KPI、Top Signals、Brand Movement、Market Structure |
| P0 | 一级导航过多且无可靠 Active State | 8 个入口，卖家分析长期高亮，1050px 以下全部隐藏 | 信息气味混乱，移动端不可导航 | 收敛为总览/市场/产品/品牌/榜单/报告，右侧 Alerts/Data Status/Methodology |
| P0 | 榜单不可快速纵向扫描 | 长标题、ASIN 独立列、Rank 与 Delta 分离 | 排名变化不突出，行宽和视觉负担过高 | ProductIdentity 合并 ASIN/类型；RankDisplay + RankDelta；52–60px 行高 |
| P1 | 产品页不是浏览器 | 只展示三个榜首大卡 | 无法搜索、筛选和浏览完整市场产品 | 改为全量产品表、搜索和 Rising/Top10/New/Falling 过滤 |
| P1 | 洞察页面主要解释“能否洞察” | Evidence Ladder、Availability Matrix、Coverage 占据主体 | 用户看不到业务洞察 | 技术条件迁入 Data Status/Methodology，主体展示已验证信号与市场状态 |
| P1 | 缺少统一暗色 Surface System | 页面为浅色，样式依赖白卡和强边框 | 与产品定位不一致，层级主要靠卡片堆叠 | 建立四级暗色 Surface、单一 Accent 和统一语义色 |
| P1 | 无统一 Loading/Empty/Error | 多处纯文字“正在…”或“暂无” | 状态不可区分、恢复路径不清晰 | 统一 Skeleton、EmptyState、ErrorState、IncompleteState |
| P2 | 图表与焦点状态不统一 | CSS 点图、局部 focus-visible | 可访问性和可读性不稳定 | 统一 Chart Token、Tooltip、事件图例、全局 focus-visible |

## Proposed Migration Plan

1. 建立暗色 Token、排版、间距、Surface、语义色和交互状态。
2. 增加纯函数 UI Intelligence 层，只组合现有排名、比较、历史和品牌元数据；不更改数据口径。
3. 先实现共享组件并用行为测试锁定格式和状态。
4. 重构 Shell、MarketContext、Data Status 与 Activity Drawer，保留旧 Route。
5. 以首页建立视觉基准，再迁移榜单、产品、市场、品牌、洞察和报告。
6. 三种桌面尺寸与移动宽度做截图、溢出、首屏和键盘 QA。

## Audit Decision

没有发现阻塞实施的数据安全风险、重大架构冲突或不可判断业务定义。所有新视觉指标必须可追溯到现有 `compareRankings`、历史 Observation 或已验证 Product Metadata；不支持的 Price Event、Review Momentum 或图片保持不显示/Placeholder，不允许推断。
