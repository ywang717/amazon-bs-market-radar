# Phase 0–4 完成度审计（2026-08-04）

## 审计结论

Phase 0–2 的设计与可执行数据模型已完成；Phase 3 与 Phase 4 的本地最小链路已完成，但真实 Amazon Best Sellers 的稳定三榜 Top 50 自动采集、完整历史基线与生产运维仍未完成。当前不应把项目描述为“前四阶段全部生产完成”。

## Phase 0：系统规划

**状态：完成，部分早期待确认项已被后续实施替代。**

- 三品类、七类配件、Category Independent 架构、质量门禁、历史追加策略和模块边界均有设计文档。
- 本地 PostgreSQL、PowerShell、Python PDF 和 Codex 自动任务已成为实际本机运行方案，早期“尚未选型”描述已过期。
- 仍未确定的是生产环境的对象存储、备份、告警、成本预算和正式合规/数据供应商授权；这些不阻塞本地积累，但阻塞生产化。

## Phase 1：项目初始化

**状态：完成。**

- 目录、配置、文档、测试、脚本、运行数据隔离和本地依赖均已建立。
- README 与早期检查点仍保留“当前无 Python/数据库”的历史描述，应在下一轮文档整理中更新为当前环境。

## Phase 2：数据库和数据模型

**状态：完成（本机可执行）。**

- 已有 001–010 迁移，包含核心观察、公共安全历史、Best Sellers 历史、机会、市场结构和排名关联的追加式表与视图。
- 本机 PostgreSQL 健康检查已验证 51 张应用表、15 个视图和 10 个已应用迁移。
- 当前 Best Sellers 捕获字段不含已验证的 Coupon、Seller、FBA、First Available Date 和结构化 Brand；模型可容纳这些字段，但数据源尚未提供，不能声称这些指标已具备。

## Phase 3：数据采集系统

**状态：部分完成，关键真实采集能力未验收。**

已完成：

- fixture、统一观测契约、质量门禁、原始 artifact、outbox、事务导入、三品类编排和 Creators API SearchItems 适配器。
- 三个独立 Best Sellers 节点已记录，Top 50 的正确加载规则已定义。

仍未完成：

- 可重复、无人工介入的三个独立 Best Sellers Top 50 实际采集器尚未形成已验证脚本；现有真实快照仅来自浏览器读取。
- 当前真实快照仅有 Pressure Washers、Sump Pumps 各 30 条，配件榜 0 条；尚未通过三榜完整 Top 50 验收。
- Movers & Shakers 采集器未实现。
- 官方 Creators API 的 Search Results 路径仍需可用账户凭证；它不能替代 Best Sellers 或 Movers & Shakers。
- 生产数据库的备份、最小权限角色、恢复演练及非交互式任务运行身份未完成。

## Phase 4：历史数据库系统

**状态：结构完成，真实市场历史仍在积累。**

- CPSC 公共安全情报拥有只追加历史、导入函数、变化视图和幂等验证。
- Best Sellers 也已有历史运行、观察、日变化和退出表；后续分析 artifact 均按版本追加保存。
- 真实 Best Sellers 只有 1 个不完整观测日，因此尚未形成任何完整三榜历史，更不能形成 7/30/90 日趋势。
- 旧 Windows 计划任务 `AmazonIntelligence-Daily-0900` 当前不存在；实际定时运行由 Codex 中的日报、周报自动任务承担，应以它们为唯一调度入口并持续监控。

## 当前必须完成的顺序

1. 每日获取三个独立榜单各完整 Top 50，并保留质量证据。
2. 首次有限周度分析固定在北京时间 2026-08-10；即使覆盖不足也必须明确披露基线不足。
3. 三榜各积累 8 个完整市场日后，周报才可将 Phase 5 的机会、市场结构、价格/星级/评论数关联与趋势作为完整覆盖结果解释；日报只记录和发现明显榜单变化。
4. 在准备生产化前补齐获准数据渠道、自动采集稳定性、备份、最小权限、告警和恢复演练。
