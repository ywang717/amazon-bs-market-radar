# 桌面报告归档设计

## 目标

在现有 Amazon Best Sellers 日报和周报流程完成 PDF 生成及验证后，将 PDF 副本保存到 Windows 桌面上的 `亚马逊bs榜单每日监控` 文件夹，便于用户直接查阅，同时不改变项目内部报告、邮件发送和健康审计所依赖的路径。

## 目录结构

```text
桌面\亚马逊bs榜单每日监控\
├─ 高压清洗机\
├─ 污水泵\
├─ 高压清洗机配件\
└─ 周报\
```

- 高压清洗机日报 PDF 保存到 `高压清洗机`。
- 污水泵日报 PDF 保存到 `污水泵`。
- 高压清洗机配件日报 PDF 保存到 `高压清洗机配件`。
- 三个榜单的周报 PDF 均保存到 `周报`。
- 文件名保持报告生成脚本产生的原始文件名，其中已经包含榜单、市场日期和北京时间。

## 架构

新增一个职责单一的 PowerShell 归档模块。模块负责：

1. 通过 Windows API 获取当前用户实际桌面路径，兼容桌面被重定向的情况。
2. 创建根目录和所需子目录。
3. 根据报告类型与榜单键选择目标目录。
4. 仅复制已经存在且通过报告流程验证的 PDF。
5. 返回归档后的绝对路径，供脚本输出和测试使用。

日报和周报脚本继续先在项目 `var/reports` 下生成并验证 PDF。验证成功后调用归档模块复制文件，随后继续原有邮件发送和健康审计流程。

## 数据流

### 日报

```text
生成项目内 PDF → PDF 验证成功 → 复制到对应榜单桌面子目录 → 发送对应邮件 → 健康审计
```

### 周报

```text
生成项目内 PDF → PDF 验证成功 → 复制到桌面“周报”目录 → 发送对应邮件
```

项目内部 PDF 始终作为邮件附件和健康审计依据；桌面文件是便于访问的归档副本。

## 重跑与错误处理

- 同一天、同一生成时间形成的同名文件使用覆盖方式复制，避免任务重跑产生重复副本。
- 不删除任何既有归档文件。
- 源 PDF 不存在、目标目录无法创建或复制失败时，归档操作抛出错误并使当次报告任务失败。
- 邮件发送不会在归档失败后继续执行，避免出现邮件已发送但本地归档缺失的状态。

## 测试

- 使用临时桌面根目录测试四种路由：三个日报榜单目录和统一周报目录。
- 验证目录会自动创建。
- 验证文件内容被复制且同名文件可覆盖。
- 验证未知榜单键和不存在的源文件会失败。
- 静态检查日报、周报入口已调用归档模块，并将归档路径包含在 JSON 输出中。
- 运行现有完整 PowerShell 测试集，确保邮件、PDF、Top 30 和健康审计行为不回退。

## 非目标

- 不移动或删除 `var/reports` 中的原始报告。
- 不归档 Markdown、HTML、JSON、快照或数据库备份。
- 不改变邮件收件人、发送时间、附件拆分方式或报告内容。
