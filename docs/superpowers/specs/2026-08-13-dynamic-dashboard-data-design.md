# Amazon BS 市场雷达全站动态数据设计

## 目标

让市场总览、Top 30 榜单、洞察中心和产品详情与每日网站同步保持一致。页面优先读取 Sites D1 中已导入的可验证数据；D1 暂时不可用或没有数据时，回退到随站点发布的最后一份已验证种子数据。报告中心继续使用现有 D1 元数据和 R2 PDF，不改变本机采集、邮件、数据库或调度流程。

## 范围

本次包含：

- `/` 市场总览动态读取最新市场日、上一可比较市场日、质量历史和三榜 Top 30。
- `/rankings` 动态读取最新三榜 Top 30，并继续支持现有前端筛选。
- `/products/[asin]` 动态读取该 ASIN 的全部可用历史观测。
- `/insights` 用动态历史计算证据等级、字段覆盖率和描述性排名变化。
- 统一公开查询服务和回退规则，避免页面与 API 各自实现不同的数据解释。

本次不包含：

- 修改网站视觉布局、导航或公开访问方式。
- 新增远程控制、登录、任务启动、邮件控制或本机路径展示。
- 修改 D1/R2 绑定、同步鉴权协议或本机日报/周报任务。
- 增加机会评分、因果判断、缺失值插值或推测字段。

## 架构

新增一个仅供服务端使用的动态数据读取层。它负责把 D1 的 `snapshots`、`category_days` 和 `observations` 还原成现有页面使用的 Dashboard 视图模型，并复用 `validateCategory`、`compareRankings`、`fieldCoverage` 与 `evidenceLevel` 计算规则。

页面与公开 API 不再直接依赖静态 `getSeedDashboard()`，而是调用统一异步入口：

1. 初始化并读取 D1。
2. 选择最新已导入市场日。
3. 读取该日三个榜单的观测和质量状态。
4. 从历史中选择最近的可比较完整市场日；只有两日同榜单均完整 Top 30 时才计算日度变化。
5. 读取历史质量序列和完整市场日数，生成证据等级。
6. 若 D1 不可用、为空或查询失败，返回已验证种子 Dashboard，并标记内部来源为 `seed_fallback`；该内部标记不暴露本机信息或错误详情。

`getSeedDashboard()` 保留为灾难回退和本地无 D1 测试夹具，不再是线上页面的默认数据源。

## 数据选择规则

### 最新市场日

- 以 `snapshots.market_date` 最大值为最新市场日。
- 页面显示的观测时间取该快照的 `observed_at`。
- 每个榜单的完整度同时参考 `category_days` 和实际观测重新校验；两者不一致时按不完整处理。
- 缺失字段保持 `null`。

### 日度比较

- 对每个榜单独立寻找最新市场日之前最近的完整 Top 30 市场日。
- 当前日和基准日都完整时，才计算平均绝对排名变化、Top 10 留存、新入、退出及大幅异动。
- 任一侧不完整时返回现有“暂不可比较”状态，不用其他榜单或静态数据补齐。

### 历史与证据

- 完整市场日定义为三个榜单均通过 Top 30 完整性校验。
- 证据等级继续使用现有规则：1 日有限、2–4 日可用、至少 5 日充分。
- 质量时间轴展示 D1 中可验证的市场日状态；种子数据只在整次 D1 读取失败时整体回退，不与线上数据混合拼接。
- 价格、星级、评论数覆盖率低于 80% 时，对应关联分析保持暂停。

### 产品历史

- 通过参数化查询按 ASIN 读取历史，按市场日升序返回。
- 产品当前信息取最新一条观测；最佳排名、在榜天数和波动区间从真实历史计算。
- D1 正常但 ASIN 不存在时返回 404，不回退到种子数据伪造线上产品；只有 D1 整体不可用时才查询种子数据。

## 页面改造

### 市场总览

服务器组件异步读取动态 Dashboard。现有 KPI、质量时间轴、跨榜单矩阵和变化指标保持布局不变，所有日期、观测数、完整市场日数及变化结论改为数据驱动。删除硬编码的“8 个连续完整市场日”和固定 8 月日期叙述，改为依据当前证据自动生成。

### 榜单页

服务器组件读取动态三榜数据后传给现有 `RankingExplorer`。市场日按钮显示真实最新市场日；筛选交互保持不变。

### 洞察页

证据阶梯、可用性矩阵、字段覆盖率和周期文字使用动态数据。关联分析仍仅描述覆盖状态，不新增因果结论。

### 产品详情

页面异步读取产品历史；标题、当前观测、在榜天数、最佳排名、波动区间和曲线均来自 D1。不存在的 ASIN 使用现有 404 行为。

### 公开接口

`/api/public/overview`、`/api/public/rankings` 和 `/api/public/products/[asin]` 复用同一数据读取层。接口继续只返回公开业务字段，捕获错误时不返回堆栈、绑定名、内部路径或秘密。

## 错误处理与缓存

- D1 查询异常：页面整体回退到种子数据，HTTP 页面仍可用。
- D1 为空：视为尚未同步，回退种子数据。
- 单个榜单记录不完整：保留真实不完整状态，不对该榜单使用种子补齐。
- 产品不存在：D1 正常时返回 404。
- 公开 API 使用现有短时公共缓存；同步完成后最多在缓存窗口内延迟显示。
- 所有 SQL 使用参数化 prepared statements；不把 ASIN、日期或类别拼接进 SQL。

## 测试策略

1. 数据读取层单元测试：
   - 最新市场日覆盖旧种子日期。
   - 三榜完整时返回 90 条观测和正确证据等级。
   - 当前日不完整时不计算该榜单日度变化。
   - D1 异常或为空时整体回退种子数据。
   - D1 正常但产品不存在时不回退种子产品。
2. 路由和渲染测试：
   - 注入一个比种子更新的 D1 市场日，确认首页、榜单、洞察和产品页均显示该日。
   - 确认页面与 API 不泄露邮箱、本机路径、秘密或内部错误。
3. 回归验证：
   - `npm test`、`npm run lint` 和 `npm run build` 全部通过。
   - 现有 PowerShell 完整测试不少于 200 项，失败数为 0。
   - 部署后公开接口与页面显示同一最新市场日、三个榜单和 90 条最新观测。

## 发布与回滚

- 不修改数据库结构，因此不生成 D1 migration。
- 构建与测试通过后发布一个新的 Sites 版本。
- 发布失败不影响本机日报、周报、邮件或数据库。
- 若线上动态读取异常，页面自动回退种子数据；必要时可回滚到上一 Sites 版本。

## 验收标准

- 每日 09:00 同步完成后，无需重新部署即可让首页、榜单、洞察和产品详情读取最新 D1 数据。
- 页面与公开 API 使用相同的数据规则和最新市场日。
- 不完整数据不会被种子数据局部补齐，也不会生成不满足门禁的变化结论。
- D1 故障时网站仍能只读访问，并明确保持最后一份已验证回退内容。
- 网站不暴露邮箱、授权码、本机路径、任务名称、数据库绑定或内部错误。
