# 周报真实分析内容修复设计

## 背景与问题

`New-BestSellersWeeklyAnalysis.ps1` 已生成按榜单分类的 `large_swings`、`new_entries` 和 `exits`，同时 Phase 5 已生成价格、星级、评论数与排名的关联结果。但 `New-BestSellersWeeklyReport.ps1` 没有读取这些明细，而是在每份 PDF 中固定写入“当前无可比较的完整榜单变化”，造成报告结论与分析产物不一致。

## 目标

- 三份周报继续保持一榜单一 PDF、一邮件一附件。
- 每份 PDF 只展示其对应榜单的数据。
- 列出本周排名绝对变化至少 10 名的产品；至少 20 名标为高优先级。
- 汇总新入 Top 30 与退出 Top 30，并显示 ASIN、产品名、日期和排名。
- 加入价格、星级、评论数与排名的关联结果，明确标注为相关性而非因果关系。
- 数据覆盖不足 8 个完整市场日时，保留“首次有限周度分析”提示，不输出趋势或因果结论。

## 设计

周报入口读取刚生成的周度分析 JSON 和排名影响 JSON。对每个榜单先筛选对应 `category`，再分别构建大幅排名变化、新入榜、退出榜和关联分析表格。Markdown 与 HTML 使用同一组已筛选数据，避免两个格式产生不同结论。若某一表为空，才输出“本周无符合阈值的记录”。

关联分析显示指标、样本量、Spearman rho、方向和强度；正文固定披露“仅表示统计关联，不代表价格、星级或评论数导致排名变化”。覆盖不足时仍可显示当周已验证的逐日变化和有限关联结果，但将其标记为初始基线。

## 错误处理

- 周度分析或排名影响产物缺失时，周报生成失败，不发送邮件。
- 榜单分类缺失时，周报生成失败，不用其他榜单数据补齐。
- PDF 验证或桌面归档失败时，不发送邮件。

## 测试与验收

- 回归测试必须证明：当周度分析存在大幅变化时，报告不得出现固定的“无变化”结论。
- 验证三份报告只包含各自榜单的 ASIN。
- 验证关联分析包含价格、星级、评论数，且包含非因果声明。
- 运行完整测试集，并重新渲染三份 PDF 逐页目视检查。
