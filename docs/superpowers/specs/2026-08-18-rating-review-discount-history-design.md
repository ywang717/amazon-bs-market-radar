# 评分、评论、优惠与排名关联设计

## 目标

扩展公开的 Amazon Best Sellers Top 30 抓取流程，使每条已发布的商品记录分别保存其卡片上可见的评分和评论数，并保存由商品详情页公开信息核验的优惠状态。将这些字段持久化到 PostgreSQL，并在 Best Sellers 日报和周报中展示。记录同一 ASIN 的优惠状态变化及排名变化，但仅作为观察结果；绝不宣称优惠导致了排名变化。

## 数据契约

每条快照商品记录保留现有字段，并新增：

- `rating`：四舍五入到一位小数的数值评分；卡片未展示评分时为 `null`。
- `reviews`：非负整数的评论数；卡片未展示评论数时为 `null`。
- `has_discount`：仅当公开商品详情页确认有一项或多项优惠时为 `true`；仅当可读取的公开详情页确认没有优惠时为 `false`；详情页无法核验时为 `null`。
- `discounts`：零个或多个对象组成的有序列表；每个对象包含 `kind`（`COUPON`、`PRICE_DROP` 或 `PRIME_EXCLUSIVE`）以及标准化 `amount`，例如 `10% off` 或 `$10.00 off`。

评分只从星级标签中提取。评论数只从紧邻该星级链接的评论数文本中提取。二者不得共用选择器或数字解析输入。仅支持以下详情页优惠信号：Coupon、可核验的划线价与当前价差额，以及 Prime 专享优惠。未获得公开证据时，不得将展示价格或推断出的价格差视为优惠。

## 抓取与校验

列表卡片仍是排名、ASIN、标题、价格、评分和评论数的来源。现有榜单和价格完整性门槛通过后，使用同一个临时上下文，通过每个 ASIN 的规范 URL `https://www.amazon.com/dp/<ASIN>` 访问商品详情页以核验优惠。榜单或价格抓取失败的尝试不会打开优惠详情页标签；恢复重试仍如既往使用全新的浏览器/上下文。

详情页访问被拒绝、要求登录、验证码、无效 ASIN、导航失败或页面不可用时，`has_discount` 保持为 `null`，`discounts` 为空。这是未知结果，而不是无优惠结果，且不会改变现有的价格完整性发布门槛。价格证据和优惠证据保持为独立且已脱敏的诊断数组。证据仅可保存规范的来源/类目/ASIN 关联和受支持的结构化状态；不得保存页面正文、原始任意 URL、Cookie、凭据或异常信息。

## PostgreSQL 历史数据

新增一项只向前兼容的迁移，为 Best Sellers 历史表添加可空的优惠状态和 JSONB 优惠列表。导入函数与现有的排名、价格、评分和评论字段一起原子性读取新的快照字段。已有历史行仍然有效，其优惠状态为未知。报表视图以稳定、强类型的形式暴露这些新字段。

数据库是可供报表使用的历史优惠状态变化的来源。仅当同一类目和 ASIN 在两个有效交易日均有记录时才构成一次变化。该变化记录前后优惠状态、标准化优惠列表以及现有的排名变化。当前或此前状态未知时，显示为不可用，且不计入优惠状态变化统计。

## 报表

Best Sellers 日报在每个商品表中增加评分、评论数和优惠列。`has_discount` 为 true 时，优惠列展示标准化优惠金额；为 false 时展示“无”；为 null 时展示“等待核验”。每个类目还包含紧凑汇总：已核验有优惠商品数、已核验无优惠商品数和优惠状态未知商品数。

周报在每个类目中增加“优惠与排名”部分，列出同一 ASIN 的优惠变化，包括两个交易日、前后优惠展示、前后排名和排名变化。还包含类目统计：新增优惠、取消优惠、优惠金额变化、优惠未变和未知记录数。所有日报和周报布局均追加固定说明：这些字段只描述观察到的共同变化，不能证明优惠导致了排名变化。

## 当前数据更新与验收

实现和自动化验证完成后，运行一次真实的无头、临时抓取。只有现有完整性门槛通过时才发布快照，生成其回执，并通过现有 PostgreSQL 导入器导入已核验的快照。为该交易日生成日报，并生成周报；除非另有请求，否则不发送邮件。核验数据库行、Markdown/HTML/PDF 内容和快照中代表性 ASIN 的评分、评论数和优惠值完全一致。

## 测试

- Python：卡片标记证明 `rating=4.6` 与 `reviews=13471` 相互独立；详情页夹具覆盖 Coupon、降价、Prime 专享、无优惠和受阻/未知结果；恢复流程验证所有成功记录，并在不完整尝试时跳过优惠详情页访问。
- PostgreSQL/Pester：迁移和导入保留 true、false 和 unknown 三种优惠状态以及结构化优惠列表；变化查询仅配对同一 ASIN 的有效记录。
- 报表/Pester：日报表格和类目汇总呈现三种优惠状态；周报表格呈现新增/取消/变化事件和非因果说明。
- 端到端：真实抓取、已核验回执、数据库导入和报表生成均完成，且不会写入敏感信息或使用已认证/绕过行为。
